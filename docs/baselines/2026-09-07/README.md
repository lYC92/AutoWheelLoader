# 自动演示轮端有扭矩、车辆不动：修复与回归

故障：`wheel torque did not produce wheel motion: 0.0000 rad/s`。
原始报错记录了四轮各 2500 N·m、299 个车辆状态、faults=0、estop=False。
现场读取到动臂 -0.200 rad、铲斗 -0.227516 rad，车辆停在 x≈-0.000267 m、base z=0.15 m。
由正式名义几何计算斗刃高度约 0 m；铲斗接触刚性地面使车辆卡住。
报错后读到的命令超时急停是脚本退出后的保护，不是原始卡住原因。

旧流程依赖出生姿态，在界面、桥和传感器初始化之后直接施加牵引扭矩。
这段等待足以让未保压的工作装置在重力作用下落地，造成启动时间相关的失败。

修复位于 `tools/ros/test_loader_soil_coupling.py`：

- 前进前制动，用关节反馈和名义重力补偿阀命令将举升/翻斗调整到铲装姿态；
- 两关节误差都小于 0.06 rad 并保持至少 0.3 s 才允许前进，准备超过 8 s 则失败；
- 铲取、举升、倒车和制动阶段保持对应工作装置姿态，卸料时保持动臂；
- 失败时主动急停，并在轮速错误中加入关节角；启动器同时保存标准错误输出。

没有增加牵引扭矩、移除地面碰撞或取消轮速/装卸/守恒检查；仍通过正式力级控制链执行。

验证：

1. 在用户原有的卡住现场运行修复后的流程：峰值车速 2.793 m/s，装入并卸出 1.670136 m³，通过。
2. 全新带观察雷达的回归：故意空等 8 秒，确认动臂 -0.200、翻斗 -0.228 rad 后再恢复姿态。
   峰值车速 2.767 m/s，装入并卸出 1.701523 m³，守恒误差 8.218e-16。
   5321 条雷达射线变化超过 5 cm，13 条穿过变化料柱；实体高度与账本一致。
3. 全新基础模式，同样延迟 8 秒：峰值车速 2.774 m/s，装入并卸出 1.684651 m³，守恒误差 -1.370e-16。

原始摘要见本目录 `loader_soil_coupling*.txt`；带雷达测试另保存料柱期望和实际高度。
回归入口 `scripts/wsl/smoke_test_loader_soil_coupling.sh [physics|perception]` 已默认使用仿真时间并延迟 8 秒，
日常演示没有人为增加这 8 秒延迟，只执行姿态准备。
